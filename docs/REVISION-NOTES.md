## 逐项落实（与审计清单编号一致）

1. **目标条件化——第 0、1 节，并同步第 9、10 节。** G1 拆成触发窗口 G1a 与健康启动预算 G1b；600 秒不再等同十分钟进系统。G2 加 RTC 供电、保存与关机层支持前提。G3 限于自有预登记入口、持久停续期和注销读回成功；REOFF 只作补偿。G4 拆硬件单次（T2/T3 待裁决）、arm_id 事务单次、独立故障救援预算三层。文档要求已落实；硬件承诺仍待未来试验。

2. **调时与通道契约——第 2、11、12.5 节。** 删除相对写入免疫调时、只影响日志及天然长期自校正的断言；新增 RTC/本 boot 单调配对区间采样、跳变停用、竞争即停用和关机过渡边界。直写与 PowerOffAlarm 分列请求量、最终剩余量、提前量及取消/切换契约；高通减 60 秒不得套用直写或重复扣除。本机未测行为统一标为 T2/T3 待裁决；不虚构厂商 API 或采样容差。文档要求已落实，厂商通道未验证，保持备选未启用。

3. **唯一权威账本与跨 RTC 事务——第 3、5 节。** 指定 HEAD 选择的快照/尾日志为唯一逻辑权威，state/seq/心跳为缓存；所有入口共用目录外稳定锁。补实例代次、tx_id、arm_id、前一 arm_id、source_boot_id、consumed_by_boot_id、stop_generation、校验链、版本/长度/类型、权限与 root 输入边界。规定 PREPARED → 硬件操作/读回阶段 → COMMITTED/FAULT，续期替代旧 arm_id 的终态、快照/HEAD 文件及父目录 fsync、轮转和坏尾处理，并列崩溃恢复表。明确不能实现跨文件与 RTC 原子提交、整体备份回滚无法绝对检测。文档要求已落实，锁/持久化实现与故障注入未执行。

4. **续期及失败语义——第 4 节，关联第 5.3、11 节。** 锁内复查停止代次，只有许可有效状态可续期；off 持久停止先于清槽。承认清后写无保护窗口，逐次记录空/旧值/未知；单次失败先解释硬件状态再决定有界重试，持久层或清残失败可立即 FAULT。保留三次连续可恢复写失败上限，达到后持久停用、尝试清自有槽并分别报警，不再声称旧值只响一次。监督不得清 FAULT。文档要求已落实，真实故障恢复性能未测。

5. **预登记主路、trap 补充——第 6 节，关联第 9 节。** 自有 root 入口完成停用/登记/清槽或改签读回提交后才执行固定命令；失败不伪称有保护。powerctl 按逗号分动作与目标/reason，覆盖 shutdown 带 reason、普通 reboot、recovery/bootloader、未知目标与空值，特殊/未知进入维护停用，SIGTERM 不单独证明关机。补 CANCEL、同 boot 未执行、命令失败/超时及显式恢复路径；未知结果不自动续期。删除毫秒保证，列锁/持久化/硬件/总链路待测分位与超时预算；普通菜单覆盖仍待 T2/T3。文档要求已落实，预算数值不得凭空标为已测。

6. **完整开机状态机——第 7.1 节，关联第 5.3 节。** 明确 UNKNOWN、DISARMED、ARM_PENDING、ARMED、STAND_DOWN、RECONCILING、FAULT、QUARANTINE；表中覆盖首次安装/空账本、坏账/目录丢失、同 boot 拉活、旧/当前/已消费/取消 INTENT、BOOT/RESCUE 尾记录、回滚、未提交布防、核销中断、清槽失败及显式恢复。先保存证据并清残验证，再持久消费和分类；同 boot 不重复 BOOT、消费或扣额。REOFF 候选绑定本次消费 boot，避免消费前后条件矛盾。文档要求已落实，首次非空槽的处置取舍见下文。

7. **统一原因分类与互斥分支——第 7.2、9 节。** REBOOT_OK 需可信普通重启及排除 RTC 的证据，REBOOT_RESCUED 需可信 RTC 与 arm_id 关联，否则 REBOOT_OUTCOME_UNKNOWN；无 INTENT 的 HEARTBEAT 分 SELF_RECOVERED、RESCUED_ABNORMAL、ABNORMAL_OUTCOME_UNKNOWN 三个互斥分支。off 原因不明记 OFF_OUTCOME_UNKNOWN，删除 OFF_MANUAL_ASSUMED；不凭期限接近/未到、boot_id 或墙钟离线时长推导原因。未知不自动关机，清残核销与原因分类分离。文档要求已落实，本机原因映射待 T2/T3，REOFF 另待 T6。

8. **救援预算、安全门槛及限次 REOFF——第 7.3、7.4、10、11 节。** 独立跨 boot RTC 预算，首布防先持久预扣、同 boot 续期复用、救援/未知不退额、耗尽不重布防；稳定健康与冷却按本 boot 单调观察复位，电量/温度未知或越界停用。REOFF 默认关、每原 off 事务最多一次持久请求、清槽失败不执行、请求未知不补发、人工/维护取消，失败隔离限频报警。ATTEMPTS_MAX 仍只属于默认关闭的备份禁用层。新增设计起点和理由见参数说明；健康接口、传感器及 T6 均未验证，不冒充已完成实现。

9. **RescueX/bootmod 共存——第 3、8、13.2 节。** 保留 RescueX 已在守护的事实，增加真机布防前离线审阅动作/文件写集要求，明确重启、关机、RTC、禁用模块、清理/恢复与健康契约；当前材料没有实现，未声称审阅已完成。RescueX 禁用须同锁清残，否则保持本模块停用并披露残留。bootmod 默认报告，显式许可拉活也必须尊重锁、身份、代次、STAND_DOWN/维护/FAULT/隔离及生命周期状态，带退避/次数上限，未定版保持只报告。唯一冲突策略为冲突即停用。文档要求已落实，离线实现审阅是后续门槛，不是本轮未完成的文件改动。

10. **资源上限与状态丢失——第 3.2、5.2、11 节。** 给出快照/尾日志/诊断/归档的文件及字节上限、8 MiB 全目录峰值、完整记录长度和收尾预留；压缩完成历史，保留所有未完成事务/消费依据/预算，放不下就停用。满盘、fsync/目录同步失败不报成功，不继续新增武装；目录删除/损坏先 UNKNOWN、读槽并清自有旧槽验证，未知归属须可信恢复确认，清后仍停用、不猜用户意图。文档要求已落实，主机 ENOSPC 与峰值验证未执行。

11. **验证矩阵与 T1/T6 标签——第 12、12.5 节。** T1 改名「无重启读写清探针」，保留本次 root/设备/空槽/+7200/11143/清空原始结果及非同时采样限制。新增审计矩阵全部类别，T2 分正常 shutdown 与插电充电层故障复现，记录供电/原因/采样/响后状态和人工退出方法；T6 升为 REOFF 启用前必测。未来探针需逐步检查返回值、受检 finally 和经校验尽力恢复，不直接复用生产事务；本轮不修改探针。文档要求已落实，未来试验均未执行。

12. **开发顺序与解除武装——第 13 节，关联第 12.2 节。** P1 分主机模拟/只读 P1a 与有限真机布防 P1b，P2 主机登记/对账及故障注入前移；三条 BLOCKER 的文档修订与主机验证完成、离线共存审阅和退出方案就绪后，才有人值守 T2/T3，之后才 24h 真机续期。新增升级/禁用/卸载协议：同锁持久停监督及续期 → 清槽读回 → 提交 → 迁移/禁用/删除；失败保留清理入口和待办。强删/离线禁用绕过收尾可能残留且不保证只响一次。文档要求已落实，实现及真机门槛未执行。

## 参数与证据取舍

- **原有数值未改：** WINDOW=600、RENEW=60、REBOOT_WAKE=240、WRITE_FAIL_MAX=3、ATTEMPTS_MAX=3；生产请求下限 240、T1 +7200、T2 +300、T3 越点后 10 分钟也保留原数值。600/240 改注为请求量，最终硬件剩余量须读回；不擅自从直写扣 60 秒。原 60–120 秒启动耗时降为待重新量测参考，不作为已验收时限。
- **新增预算设计起点：** RTC_RESCUE_MAX=1/incident，先预扣以覆盖布防后未记账的崩溃；STABLE_RUN 与 COOLDOWN 各 1800 秒，可并行、本 boot 重新计时，以避免救起立刻重布防。低电 20%/高温 45℃ 是保守停用起点，单位和路径未经验证时停用；待有人值守定版。REOFF_MAX=1/原 off 事务，默认关闭，防失败循环。以上是审计要求新增机制的明确起始值，不是修改既有默认值，不代表热安全或可用性已实测。
- **新增存储设计上限：** 快照/尾日志各每份 1 MiB，切换各可有两份；诊断 4×256 KiB、归档 2×1 MiB，缓存/其他临时最多 1 MiB，全目录峰值 8 MiB；单记录 8 KiB、尾日志预留收尾 64 KiB。理由是将长期增长和切换峰值纳入同一预算，不能为保上限丢未完成事务；预留不抵御真实满盘。数值需主机轮转/ENOSPC 检查，本轮未执行实现测试。
- **PREP-REPORT 与审计的证据冲突：** PREP 的「相对偏移精确成立」「RTC 被系统调时也不会长期漂移」「前置全部满足可进持续续期 P1」属于超出原始 T1 的推断。按已接受审计取舍，只保留本次读写清成功、非 Unix 基准观测和组件存在；7201 差值承认串行采样，不用作漂移或免调时证明，开发顺序以本次门槛为准。不修改 PREP-REPORT。
- **清旧槽与不抢外部槽的张力：** 审计同时要求启动/状态丢失后清旧槽和冲突停用。修订限定：可识别自有旧槽尽早清除并验证；首次安装非空或状态丢失而归属不明时，先 UNKNOWN/QUARANTINE、读槽留证据，可信恢复入口确认后清除验证，期间禁止续期和自动关机。这防止把别人的闹钟当本模块旧值盲清，代价是未知期间不能承诺自动清残；不静默恢复旧武装或猜用户意图。
- **早期清残与响后取证：** 生产尽早轻量取证并清残；验证矩阵的响后/回拨观测仅限有人值守专项测试，测试阶段不立即新布防，不能让取证例外削弱生产清残协议。
- **预算与可用性取舍：** 不能证明未消耗救援则按消耗结算；确认健康/冷却前停用会出现无保护期，明确接受该代价以限制持续故障的耗电/发热循环。预算不能证明硬件不复响或处理从未进用户空间的故障。
